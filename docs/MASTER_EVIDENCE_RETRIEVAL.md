# 母版事实检索增强 · 轻量 RAG 第一阶段（2026-11-08）

## 目的与范围

让 CraftCV 的「JD 岗位匹配」与「AI 单项润色」在**用户主动发起对应 AI 操作**时检索已有的母版来源候选，减少重复读取文件和凭空推断。此阶段仅使用 IndexedDB 中已经识别过的结构化事实，**没有引入 Embedding、向量数据库、额外向量模型 API、云端文件存储，也不会自动重读图片/PDF**。

技术路线：检索增强（retrieval-augmented prompting），而不是声称已部署了完整语义 RAG。数据规模小（当前每份母版最多 12 个文件），优先确定性匹配与来源约束；当项目叙事、工程日志和多岗位 JD 数量显著增长后，再评估本地 embedding + 关键字混合检索的价值。

## 数据链路与接口

1. 用户从母版上传原始 PDF/照片，只有这一步按现有规则触发视觉模型读取；识别结果以原件、SHA-256 和提取来源存入本地 IndexedDB。
2. 用户主动点击 JD 诊断或打开 AI 单项优化时，浏览器读取母版候选，运行既有的 \`auditEvidence\`。有来源冲突、值与摘录不一致或与当前简历有明确差异的字段，不作为生成上下文。
3. \`masterFactRetrieval.ts\` 根据岗位文字或正在优化的类目做本地术语及字段筛选，按相关性排序，最多保留 **10 条**；目前只允许教育、竞赛/奖项、证书类候选。不会把未经确认的实习职责、项目成果或个人归属直接送入生成上下文。
4. 传给既有 \`/api/ai/jd-match\` 或 \`/api/ai/optimize-section\` 的仅是 \`masterFacts\` 数组，每条含 \`sourceId,target,scope,label,value,quote,status\`。不发送 Blob、文件名、整个资料库、身份证/电话/邮箱等识别字段。服务端再次检查类型、字段、长度、数量与敏感标签。前端岗位匹配可展开查看本次提供的候选和来源编号。
5. 模型将全部证据候选视作不可信、非认证资料，仅可用于提示需要补充的证据或提醒核查；当前简历原文没有的经历、技术、数值、荣誉、技能和职责不得直接写入正式简历，继续执行原有 RGS 防编造检查以及人工预览/确认。

## 安全与使用边界

- **用户动作和第三方处理**：用户已经选择模型、主动启动 JD 诊断或 AI 单项润色时才检索并向该模型附带候选文字；不会后台同步，不会为检索额外访问模型。界面提示本次可能向云端模型发送精简候选文字。请勿把本地缓存视为跨用户隔离加密保险箱。
- **不读原件**：模型只收到本地选出的候选字段与短引用，不读取原始图片/PDF，重复运行也不重新调用附件读取模型。但正常生成/诊断操作本身仍然产生一次模型请求及潜在费用。
- **失败回退**：母版库不可读时，继续使用已有简历和 JD/原条目，明确不能据此宣称已参考母版。没有相关或安全候选时发送空数组。
- **严格范围**：这不是证书真实性、学历核验或所有岗位语义检索服务；来源候选不等于已确认事实。当前诊断/润色不自动采用母版缺失字段，不自动写入事实账本，也不自动给出简历「投递合格」结论。
- **第二、三阶段（已实现的有限范围）**：用户可明确采用可唯一定位的教育字段，并在第三阶段独立保存加权均分、课程成绩和显式新增的证书/奖项；采用值及来源记录写入当前版本 `factLedger`，支持撤销，同一附件跨岗位复用但不自动修改其他版本。既有 JD/单项优化会使用当前简历中的采用值，检索器不再额外发送同一已采用字段的 OCR 摘录。进一步的跨岗位自动同步、项目叙事、Embedding/混合检索仍待设计和测试。详见 [结构化母版事实](STRUCTURED_MASTER_FACTS.md)。## 验收

\`node --test tests/masterFactRetrieval.test.mjs\` 验证相关条目的筛选、冲突排除、隐私屏蔽、数量限制与不可信引用提示。同步执行全量 node 测试、直接 TypeScript 类型检查、复用当前 dist 的 Vite 生产构建和已有隔离 Chrome 附件回归；**没有配置真实云端供应商，因此模型实际生成的正确性/费用尚待真机检查**。
