**解释：** 结果只是预先人工标注的合成样本与确定性规则是否一致，不代表 AI 实际写作质量、语义准确率、客观幻觉率或安全性的统计估计。

继续保留原有数字、技术栈、原文引文、完成状态检查；新增规则也在最终用户确认采用之前生效，不能通过绕过首次筛选直接进入岗位稿。

## 3. 实际模型评测入口（需要明确授权才运行）

先在本地 CraftCV 后端配置可用模型，并且启动本地服务，再显式执行以下命令。示例仅为已经安装的本地 Ollama，实际模型名称需要从公开模型列表中核实：

    node --import tsx scripts/evaluateRoleResumeQuality.mjs --live --model=ollama:实际模型ID --max-cases=1

- --live 是**明确真实模型调用**，不会由自动单元测试触发。默认最多 1 组岗位；指定 --max-cases=4 才会逐一检查全部四组。
- 评测脚本只连接 http://127.0.0.1:3000 的本地 CraftCV 服务，后端仍使用现有的模型 ID 白名单，拒绝脚本提供任意外部 URL。
- 云端模型可能产生费用，必须事先确认模型、预计调用次数和预算，执行时还需显式带 --approve-cloud-cost；该参数**不是费用上限**，现有接口不返回精确 Token/价格信息，无法声称具体账单。
- 只发送合成样本中定义的岗位、JD 和自由描述；不读取本人真实浏览器母版、Word/PDF、学校记录。
- 输出复用 _private/test-artifacts/role-quality-qa/live-report.json 和 live-summary.md，保存模型建议、原文片段、校验结果和待人工打分栏。
- HTTP 错误、返回无有效候选、超时分别记录，**不自动重试**，避免重复费用。

## 4. 真实模型人工审查协议（尚待执行）

按四个独立维度对每份候选打 1–5 分，未打分时保持空值，不能把机器规则通过当成人工评分。

- **真实性**：不把 JD 需求、同事成果、别的项目技术栈和责任转成求职者经历；数字、学历、证书、业务收益不可虚构。
- **职责与阶段**：参与、协助、负责、主导和已验收、仍在测试的边界不能颠倒；原文明确不包含的工作不能被反向认领。
- **岗位表达**：嵌入式、测试、运营、资深交付按岗位采用相应术语与表达，不强制所有人是应届工程师或使用同一 STAR 模板。
- **信息完整性**：保留关键技术方法、原有指标及统计口径，避免将真实工程细节删成泛化形容词；无数字也可强调真实解决过程。
- **版本验收**：对比两份完整 A4、审查所选改动、确认后新增独立岗位版本、不覆盖原母版，最后核查正式 PDF。

初步建议：零已知严重虚构事实放行；所有高风险建议必须人工核实；四种岗位各保留真实模型输出和拒绝记录。发布质量门槛应在模型样本充足且评分一致性可检验之后确定，不能因四个样本便宣称完全可靠。
