# CraftCV-Studio · 结构化母版事实与多岗位复用

更新：2026-11-08 · 与 RGS 第 11.25 节配套

## 1. 目标、约束、交付边界

完成「共享原始证据 → 分类整理 → 人工采用 → 只写当前岗位简历 → 可追溯与撤销」。母版附件、提取结果仍由浏览器 IndexedDB 统一保存，容量与 SHA-256 去重规则沿用现有版本；**不引入第二份原始文件存储、向量数据库、额外模型或后台同步**。岗位简历使用原有 localStorage 版本结构，每个岗位可独立决定是否采用。历史简历中不存在新增可选字段时依旧按原版式加载。

这一阶段的「复用」指**相同证据无需重新识别，可在多个岗位版本中各自采用**，不是将某个岗位的改动强制同步到所有版本。若岗位 A 采用某成绩，岗位 B 的数据不会自行变化；从 A 明确派生新版本时，原有版本复制规则仍适用。

## 2. 数据与显示

| 母版事实类型 | 简历存储位置 | 采用规则 | 默认投递版面 |
|---|---|---|---|
| 教育学历/专业/入毕业时间/GPA/排名 | \`education[id]\` 原字段 | 学校名称规范化后必须唯一且精确匹配 | 旧模板保持原样 |
| \`education.weightedAverage\` | \`EducationItem.weightedAverage?: string\` | 只更新加权平均分，不触碰 \`gpa\` 或原有复合成绩 | 结构化留档；不重复输出 |
| \`education.courseGrade\` | \`EducationItem.courseGrades?: {id,course,score}[]\` | 对应学校必须唯一、课程名称非泛称、成绩为 0–100 数值；课程名称单独匹配/去重 | 结构化留档；不自动输出全部科目 |
| \`certificate.name\`、\`award.title\` | 原有 \`awards[]\`，可选 \`credentialType\` | 明确采用名称后才允许创建新条目；已有同名只使用唯一条目，防重复 | 进入现有证书与荣誉版块 |
| \`certificate.level/date\`、\`award.level/date/issuer\` | 对应 \`awards[id]\` | 精确关联已经存在的证书/奖项名称；日期和赛事年度不混同 | 按现有模板显示 |

课程成绩保留**课程名和数值**的结构，不把数字串塞进 GPA 或一整段「核心课程」。编辑器可修改和移除课程成绩，且有独立「加权平均分」输入框。职业证书、竞赛奖项复用已有编辑区，增加类型下拉框和颁发单位、日期，避免给所有模板新建不兼容章节。只有用户确定要呈现在投递版面上的内容才应按岗位与页数审阅后选入现有可打印字段；不把几十个课程分数自动堆到 A4 上。

## 3. 证据边界与安全

- 首次上传按原流程自动识别；同一字节文件再上传只复用已有识别结果。自动索引、跨文件一致不意味着发证机构审核。
- 「核对并采用」必须逐项展示原件来源、摘录、旧值、新值，确认才应用；候选必须与引用原文对应、没有跨材料冲突或歧义。不能仅因模型自称置信度高自动创建证书。
- 正式简历数据在原有撤销历史中更新；\`factLedger.version=1\` 记录字段路径、\`evidence:<id>\` 来源、\`candidateConfirmed=true\` 和 \`status=user-asserted\`，绝不升级为 \`verified-source\`；\`cloudAllowed=false\`。来源文件名与完整 OCR 文本不会复制进简历 JSON，但采用的简历值及来源 ID 会进入备份。手工改变分数、课程名称或源字段后需要重新核实，旧确认状态失效。
- 可新建证书/奖项的**名称**，但不能仅凭未知来源的等级或日期新建记录；必须先有可唯一定位的名称。个人贡献、项目性能、实习责任仍不自动凭 OCR 建造。
- 所有数据仅保存在该浏览器站点环境；切换浏览器、清理数据或跨设备需另行迁移。删除母版附件会造成对应来源 ID 找不到原件，已有岗位版本字段不会在后台被删除或重写。云端模型依赖用户明确触发的生成操作，检索阶段不主动发送新原件。

## 4. 兼容性与验收

无需迁移旧 JSON/IndexedDB。新增 \`weightedAverage\`、\`courseGrades\`、\`credentialType\` 均为可选字段，旧条目在读取、打印和手动编辑时不强制补写。新的课程分数字段只留档，不自动改变默认 A4/PDF，因而与旧 12 套模板布局分离；需要逐模板展示课程分数时应进行排版及 ATS 验收后再启用。

执行 \`node node_modules/typescript/bin/tsc --noEmit\`、\`node --test tests/*.test.mjs\`、\`node node_modules/vite/bin/vite.js build\`、\`py -3.12 -B tests/evidence_browser_qa.py\`；使用匿名模拟数据覆盖证书新建、课程成绩和均分独立性、重复与冲突、来源记录、不同岗位独立采用、编辑后确认失效、撤销和后端入参保护。**没有真实模型识别精度、学籍/证书真伪或整套 PDF 投递合格的本次认证。**

## 5. 后续约束

后续可建立「已采用事实按岗位挑选展示」的可视化预览（带页数与 ATS 守卫），完成时再考虑从当前母版检索扩展到项目事实、技术文档与本地 Embedding。任何跨岗位自动回写都需单独权限与冲突策略，不能由一次点击默许。
