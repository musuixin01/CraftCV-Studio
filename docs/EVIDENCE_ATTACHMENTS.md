# 母版证据资料 · V2 自动读取与去重

## 目标与术语

顶部「母版资料」是一份**所有简历岗位版本共用的候选事实来源库**，不是某一个岗位的正式投递简历。上传成绩单、奖状、职业技能证书、实习证明 PDF/PNG/JPG/WebP 后，自动读取并将原件、模型识别结果、来源摘录及待核对状态保存在当前浏览器 IndexedDB。单件不得超过 8 MB，母版最多 12 份不同的文件。

## 使用流程

1. 在顶部选好支持该文件的模型，打开「母版资料」。界面在上传前明确显示模型是**本机**还是**云端**，以及云端处理个人资料、费用和留存风险。
2. 点击「上传并识别」选择附件。**无需额外授权复选框或逐份点击读取**。新文件先保存到本地，再向本次选定的兼容模型发送原件；模型未配置、格式不支持或调用失败时仅保留为「未识别，待处理」，不伪造结果。
3. 使用浏览器 Web Crypto SHA-256 按实际字节内容去重，和文件名无关。已识别文件上传重复副本时，直接复用本地来源及结果，**不会再次发起 AI 调用**。批次内相同文件也合并。未识别文件可在模型准备好后点击「识别待处理」；识别成功（包括 0 项）以后不会自动重读。
4. 所有岗位版本看到同一份母版。识别候选保留原始文件、原文摘录和自动异常提示。可唯一关联现有教育/奖项字段的候选，用户核对后可点「核对并采用到当前版本」；其余材料保留在母版，不自动创造学历、证书、技能或项目贡献。5. 删除母版附件会影响所有岗位版本的可见来源及本地识别缓存，因此删除前必须再次确认。清除浏览器站点数据也会造成丢失，原件需自行保管。

## 兼容性、隐私、安全

保留原 IndexedDB 数据库 `craftcv-private-evidence-v1`，只将 Schema 升级至 v2，新增唯一的内容哈希索引；历史按岗位保存的记录**不会被删除或覆盖**，也会在统一母版内展示。旧记录无哈希时按需计算内容指纹，重复上传会复用历史识别结果。不自动搬迁或复制旧附件，避免额外占用磁盘空间。

上传按钮即本次读取动作，因此界面必须提前显示当前模型和可能的云端风险；未被上传的新文件不应后台访问。上传不附带整份简历，不跨模型自动回退。服务端仍执行文件名、媒体类型、格式签名、大小、base64 和响应结构校验；返回的事实仅是 OCR/视觉模型的**待核实候选**。云端上传后的内容无法通过关闭弹窗撤回。

资料原件、完整 OCR 候选不写入 Git/public，也不随简历 JSON/PDF 导出；但**用户明确采用到简历的字段值与本地来源 ID 会进入当前版本的 JSON 备份**。当前浏览器的 IndexedDB 不是端到端加密存储；共享设备和站点数据清理都有风险。跨设备附件同步、加密保险箱、DOCX 附件解析及真实模型准确率/费用实测尚未完成。
## 自动整理与异常优先核对（v2.1）

上传并识别后，系统**在本地**对已经保存的结构化事实运行确定性检查，不再次调用 AI，不要求用户逐个确认清晰候选。结果按当前简历和全部母版材料重新计算，原件及识别缓存保持不变：

- **自动归档**：有明确字段、所属学校/奖项（学校名称等根字段可无父级）、识别值能在模型提供的来源摘录中找到，且与可安全关联的现有简历字段、母版其他对应字段没有冲突。自动归档只是「可检索的来源候选」，不是学历、成绩或证书的官方核实。
- **多材料一致**：至少两份内容 SHA-256 不同的材料中，同一机构同一字段的识别结果一致。不同文件内容不一定代表独立权威来源（例如同一证书两张照片），因此只显示「多材料一致」，不自动升级为已认证/已确认。
- **需要核对**：识别值在来源摘录中找不到、关键信息缺少归属、同一字段的不同候选值发生冲突，或对应的正式简历字段存在明确差异；模型识别备注也单独提示。系统默认只展开异常项，其他字段折叠但可点「查看全部」。
- **必须保留的口径差异**：GPA 与加权平均分分别存储；不同课程的分数不互相比较；竞赛年度与证书颁发日期不互相覆盖；团体奖项与个人奖项不混为一项。无法确认机构/字段身份时不推断，也不制造「已验证」状态。

核对分类是本地可复现的规则计算结果，随当前简历版本变化；不等于官方机构查验。对于可唯一定位的候选，支持用户明确确认后应用到正式字段，其余项目仍需人工编辑。
## 对候选事实明确采用到当前简历（v2.2）

自动归档不是直接填写正式简历。用户可按需展开一项候选，查看来源原件及摘录后点击「核对并采用到当前版本」；操作会对比旧值、新值、附件来源，确认后仅写入**当前岗位版本中的那个字段**，并使用已有 `factLedger` 记录来源 ID、采用时间和「用户已采用」状态。之后在简历编辑器改动同一字段，采用状态会自动失效；原有 Ctrl/Cmd+Z 撤销与版本历史继续生效。

可安全定位的既有学校/奖项字段在用户确认后才修改；v2.3 起也可显式创建证书/奖项名称、记录对应课程单科成绩和独立加权均分。无法精确定位学校/奖项、无法核对摘录、材料存在矛盾时保留待人工处理。复合 GPA 与加权均分不会因为单一成绩而被覆盖。详见 [结构化母版事实与多岗位复用](STRUCTURED_MASTER_FACTS.md)。
**采用 ≠ 机构认证。** `factLedger` 使用 `user-asserted` 而不是 `verified-source`；本次来源信息只保留本地附件 ID 与非敏感字段名，`cloudAllowed=false`。正式简历字段本身可以按用户之后发起的岗位诊断/润色正常使用；不会把源文件、识别摘录、文件名当作新的隐式云端发送权限。共享母版的 Blob 和完整 OCR 候选仍不包含在简历 JSON/PDF 中，但**已采用的字段值和简短来源 ID 会随简历 JSON 备份**；不要把 JSON 备份当作经过官方核验的证书。

## 结构化事实与跨版本复用（v2.3）

课程成绩、加权平均分、证书与竞赛奖项分别建模；同一份母版附件在所有岗位版本中均可查阅和采用，但仅更新用户当前确认的岗位版本。已采用值进入该版本 JSON 和原有事实账本，来源原件仍保存在本地 IndexedDB，不自动同步全部版本或将全部成绩输出到 A4。字段映射与回归说明见 [STRUCTURED_MASTER_FACTS.md](STRUCTURED_MASTER_FACTS.md)。

## 回归验证

`npm run lint`、`npm run test`、`npm run build`；`py -3.12 tests/evidence_browser_qa.py` 用匿名模拟图片覆盖“选择即识别、无复选框、内容哈希去重、重命名不重复请求、刷新恢复、删除确认”；真实云端账户与真实证书准确率不在本次测试范围。
