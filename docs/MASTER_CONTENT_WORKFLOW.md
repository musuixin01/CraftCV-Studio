# 母版内容库与岗位版生成（2026-11-09）

## 定位

沿用既有本地 IndexedDB（数据库 `craftcv-private-evidence-v1`）。Schema v3 已有附件 `attachments` 与项目／工作内容区 `contentEntries`；v4 增加 `sourceDocuments` 结构化来源；现升级到 **v5**，在同一个数据库增加 `masterFiles` 保存用户直接添加的原文件，默认不提取、不修改。仍是同一个数据库，不删除或覆盖旧版附件及工作经历，不创建平行母版库。
## 使用流程

1. 在「内容编辑」完善当前**真实**简历中的项目、工作或实习。演示版不允许收录为本人素材。
2. 顶部「母版资料」→「可复用项目与工作经历」，勾选本人已确认的条目并点击「确认收录」。本地保存来源版本和一份可复用快照。无需额外 AI 或上传。内容库支持单条移除，不自动修改现有简历。
3. 「简历版本」→「从母版生成岗位版」：输入目标岗位及可选 JD，按本地关键词关联排序，从 `contentEntries` 选最多 14 条项目/工作经历，同时可从已保存的 `sourceDocuments` 选最多 20 条教育/技能/奖项。选择后先打开只读 A4 预览，确认才新建岗位版本。只替换明确选择的教育、技能或奖项模块；如选择经历，则按所选内容重组项目/工作模块。岗位变化后清空旧总结；原稿、母版及旧版本均不覆盖，JD 不会自动补充缺失技能。
4. 「AI 单项润色」「JD 匹配」仅在用户主动发起时读取资料：已成功「提取并保存到内容库」的 Word/PDF **直接使用最新结构化字段**（教育、项目、工作、技能、奖项、总结），按来源 SHA-256 排除对应原件，不再解析文件或使用过期原文；未提取的原件才按需本地提取相关文字。**不自动上传文件原件或整份母版**；云端模型可能处理这些有限摘要，未核实事实不能自动写入正式简历。

## P0-A｜Word / PDF 原件优先、按需一键提取（当前第一版）

- **默认路径：** 在「母版资料」点击「添加 Word / PDF」，通过文件选择器添加 DOCX 或 PDF。系统只核验格式、容量和 SHA-256，然后将原始 Blob 保存到同一个 IndexedDB 的 `masterFiles`；添加后不解析、不修改、不生成条目、不请求 AI。按文件内容去重，单件最多 12 MB，最多 40 份/合计 60 MB。
- **AI 按需读取：** 主动点击「AI 单项润色」或「JD 匹配诊断」后，按 SHA-256 检查已保存的提取来源。已提取的文件从 `sourceDocuments` 组装最新结构化字段摘要，不再读取该文件 Blob、重新解析旧原文或依赖 `sourceLines`；未提取的文件才在本机按需解析。两类摘要各最多 2 份、每份最多 2600 字并隐藏常见联系方式；云端模型可能处理这些**文字摘要**，不上传原始 Blob 或整份文件。
- **需要修改时：** 在已添加的文件旁点击「一键提取」，DOCX 用 Mammoth、PDF 用 PDF.js（含本地中文 CMap/标准字体）提取文本；系统按教育、项目、实习/工作、技能、奖项和总结进行初步分组，打开**可编辑副本**。默认不要求逐条勾选；用户可直接保存，也可先修改字段、增加或移除误识别项。未点击「保存到内容库」前不会写入结构化记录。
- **保存和继续编辑：** 点击「保存到内容库」成功后，提取结果原子写入 `sourceDocuments`，项目与工作经历同步写入 `contentEntries`；从此开始直接使用结构化内容而不读取对应原文件。之后可以再次编辑，AI 下次使用的是最新保存的值。仅打开提取窗口而不保存不视为完成提取。旧岗位稿和原件不变，教育、技能、奖项及总结保留在 `sourceDocuments` 中。
- **旧记录兼容：** 原有附件 `attachments`、`contentEntries` 与 v4 `sourceDocuments` 均保留。当前 Schema **v5** 只新增 `masterFiles`，不另建数据库。过去已结构化导入的来源仍可编辑；不会凭空补造缺失的原始 DOCX/PDF Blob。
- **限制：** 复杂 Word 文本框、表格、长 PDF 分栏仍需人工核对。扫描型 PDF 可先作为原件保存，但没有可靠文字层时「一键提取」提示需要 OCR 或手动录入；本版没有实现真正 OCR。
- **验收：** 匿名 DOCX、中文文字型 PDF、图片型 PDF 的 Chrome 交互及 IndexedDB 写入/源文件保留测试通过；同一 DOCX 实测提取前可按需读原文，提取保存后不再触发原文件 `arrayBuffer`，编辑保存后读取更新值且不引用旧值。真实复杂样本和外部 AI 生成质量仍未实测。


## P0-B｜跨栏目岗位选材、可选 AI 专业改写及完整 A4 审阅

- 数据来源：从原有 `contentEntries` 读取本人确认收录的项目/工作经历；从已提取并保存的 `sourceDocuments` 读取教育、专业技能和奖项/证书。**不读取这些来源的 Word/PDF 原件或 `sourceLines`**。未提取的原文件不自动转成正式学历/技能。
- 岗位相关性：以目标岗位和可选 JD 做本地关键词排序；「按岗位推荐」仅选择实际存在且匹配的条目，用户仍可取消、改选或手动加入。不是 ATS 官方分数，也不是 AI 自动创作。
- 版本组合：教育、技能和奖项分别只在勾选对应条目时替换，其他类别保留当前真实版本；选择项目/工作经历时仍遵守已有重组逻辑。对应的旧事实账本路径不会跟随被替换的条目；新条目 ID 含结构化来源引用。
- **提交前验收**：生成器先检查母版条目是否在其他标签页发生变化，使用现有 `ResumePreview` 只读渲染完整候选稿；预览阶段不改变版本。确认创建前再次复核已选数据及原始简历快照；本地存储成功后才更新 UI。失败不出现“只在界面创建但未持久化”的半完成版本。
- 验证：匿名 Chrome 环境确认从已保存 DOCX 结构化源和已收录项目/经历共同生成岗位稿，预览前无保存，确认后原槽及原母版不变，整个流程外部 AI 调用为 0。单元测试覆盖重复/失效选择、纯教育等跨栏目选材、事实账本、原件无需重新解析。
- **可选 AI 改写（已接入，真实模型质量尚未验收）**：用户先查看本地完整 A4 候选，再主动点击「用 AI 专业改写」，确认所选模型及发送数据范围；无模型时保留本地预览和创建功能。调用统一 RGS 的服务端 API `/api/ai/draft-role-resume`。仅发送当前候选中适合安全改写的自由描述（字段长度 24–1600 字，共最多 48 字段和 16000 字）及目标岗位/最多 3000 字 JD；不传原 Word/PDF、附件 Blob、完整 ResumeDocument、结构化身份/学校/日期/绩点。**自由描述或 JD 若自行包含机构、个人信息仍可能被云端模型读取**，因此要先看确认提示。较短或敏感字段保持原样，不冒充已重写。
- **事实守卫与审阅**：模型必须返回原文字段 ID、完整改写、逐字原文引文和具体理由；服务端和前端拒绝无来源引文、新数字/技术、参与变主导、进行中变已通过等高风险文本。结果只作为建议，已有完整双 A4 对比组件显示左侧带颜色标记的原文、右侧干净拟采用稿；每条可取消/勾选，部分需本人核对的建议不默认选择。保存时重新核实母版来源及当前版本，全部改写只进入新岗位版，不覆盖原母版和历史岗位稿。
- **验证边界**：Chrome 匿名测试以本地模拟模型完成点击 → 请求范围检查 → 拦截编造的候选 → 完整 A4 审阅 → 取消/选择 → 保存新版本；无模型回退、本地版本隔离、服务端非法身份字段拦截也已实测。**未用真实外部 AI 检验语义质量与幻觉率**，新增四岗位匿名[质量评测基线及模型测试入口](ROLE_RESUME_QUALITY_EVALUATION.md)，实际模型列表为空；最终 PDF 仍需单独验收。

## 工程边界

- 项目/工作经历存于现有 IndexedDB 的 contentEntries store，单条不超过 24 KB，总数不超过 120 条，按来源版本和条目 ID 防止重复录入。
- 基础 JD 排序是**本地术语关联**，不是完整深度语义检索，更不是招聘方 ATS 评分。
- 内容库的本人确认不等于第三方认证；未证实的数字、测试结果或职责归属不能由模型补造。
- 此阶段不自动读取 C 盘绝对路径下的 DOCX；用户尚需通过已支持格式导入真实简历，再选择项目或工作经历收录。软件不会扫描私人目录。
- 当前的「生成岗位版」是**本地选材 + 独立版本创建**，AI 逐项润色仍需用户发起和确认；不会自动发生额外模型收费。
- 现有 JSON 备份不包含母版 IndexedDB 的原件或 contentEntries；清除浏览器站点数据可能丢失母版。后续应补母版内容单独导出/恢复及冲突验证，不能声称备份已完整。

## 验收

执行 Node 全量测试、TypeScript 编译、Vite 构建、Git 差异检查和隔离 Chrome 验收，确认旧 IndexedDB 附件仍可正常打开、新素材不会改动源版本、演示资料不能加入正式母版、无模型调用也能生成岗位稿。不得提交或推送仓库。
