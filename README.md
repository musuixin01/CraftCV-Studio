# CraftCV Studio

面向技术岗位求职者的本地优先简历工作台：编辑真实经历、管理多个岗位版本、查看 A4 实时预览，并可选用 AI 辅助写作与公开 GitHub 工程证据分析。

**项目目标与研发接续：** [阶段目标与验收基线](docs/STAGE_GOALS.md)。Word（DOCX）和 PDF 可以直接添加到本地母版，**默认保存原件、不提取、不修改**；AI 仅在用户主动调用时读取相关文本片段，需要编辑时点「一键提取」形成可编辑副本。接下来完善完整岗位简历生成和润色，**母版全量备份恢复留到最后阶段**。功能状态以最新测试和 [母版内容库工作流](docs/MASTER_CONTENT_WORKFLOW.md) 为准。

## 已实现的主要能力

- **简历编辑**：学历、项目、技能、获奖及自定义内容；实时预览、模块布局与多种模板。
- **可视化模板库**：原有 4 款 + 8 款原生参考风格。打开编辑器，点击右侧预览区上方的「更换模板」，选择模板后实时重排同一份简历。参考来源包括 Reactive Resume、RenderCV、Awesome-CV 和 ResumeSample；[来源与授权说明](docs/TEMPLATE_REFERENCES.md)。
- **本地版本**：浏览器 localStorage 存储，支持 JSON 导入和备份。数据不会自动跨设备同步。
- **两种 PDF**：「一键高清 PDF」保留当前选择的视觉模板并下载图片式 PDF；「ATS 文字 PDF」使用同一份事实数据生成独立黑白单栏打印版（不带照片），Chrome/Edge 另存为 A4 可检索文字 PDF。多页前提示，打印每页留 12mm 页边距，不强制删减真实内容。
- **校招单页目标**：可在「模板与版式」或预览顶部选择「严格单页 / 允许多页」，旧简历默认仍允许多页。严格模式对当前视觉模板和独立 ATS 打印版分别做一页 A4 预检；超页禁止继续导出，高清图片版还会在实际截图分页后再次校验，不会截断第二页。点击「尝试单页排版」只调整留白与行距、保留标准字号和各模块独立间距，不自动删除经历。若仍不能单页，需要本人筛选与目标岗位不相关的信息，或主动改回允许多页。**注意：ATS 最终页数仍以浏览器另存的真实 PDF 为准。**
- **AI 一键精简 / 无 AI 排版提示**：点击「AI 一键精简」后先检查模型；有配置的 AI 模型自动分析目标岗位、提取可安全精简的描述，默认准备好可应用方案，用户先看到两份**完整 A4 简历**并排对比（左原稿、右拟采用稿）：沿用当前简历模板和所有模块，所有删改标记集中显示在左侧原简历中（旧文字红色删除线、拟新增文字蓝色「＋」标记），右侧是完全无审阅标记的修改后完整 A4；为给两份简历腾出空间，审阅区使用接近全屏的 A4 双栏工作台，顶部仅保留紧凑摘要，逐项修改清单默认折叠、展开后可立即更新右侧拟采用稿。两份支持同步放大、缩小、适应宽度；放大后可分别按住鼠标拖动、触屏滑动或使用方向键查看。平板和手机提供「修改前 / 修改后」切换，最后点击一次「确认精简」。一次应用可撤销，但不保证自动达成一页。无模型时不上传简历，只提供两个明确选择：确认压缩全局间距、行距和页边距（保留字号、内容及各模块独立设置，可撤销），或打开现有 AI 模型配置说明，配置后重新点击精简；不会假装 AI 成功。不主动上传姓名、联系方式、照片、成绩、学校等结构化信息或完整简历；含明显电话号码、邮箱等联系方式的自由文本会被排除。仍需留意自行写入描述中的其他敏感内容，云端模型会接收本次选中的编辑文字和目标岗位。具体保护及验证见 [11.15](docs/RESUME_GENERATION_STANDARD.md)。
- **岗位导向的 AI 专业精简**：不再以减字数作为唯一标准。AI 必须展示原文技术证据、岗位相关性（AI 推断而非 ATS 分数）、改写理由和可能损失的技术含义；另列出值得保留的关键工程证据。支持粘贴真实招聘 JD 后重新分析；有 JD 的建议必须逐字引用该 JD，无 JD 时明确提示仅为岗位方向初评。通过规则校验的候选默认选中，修改对比默认可见，可直接取消个别建议；岗位证据和 JD 详情可按需展开；点击一次「确认精简」才整批应用，绝不自动删除经历。详见 [11.16](docs/RESUME_GENERATION_STANDARD.md)。
- **适度专业包装，不机械压字**：允许在真实工程事实基础上重写句式、突出实际技术亮点，必要时等长或略长；不允许虚构主导、指标或验证成功。对参与角色、项目阶段的模糊改写给出醒目提示，默认不选但可在核对后选用；其他合规润色仍一键确认。差异栏如实显示净增减字数，最终页数依据 A4 排版检查，详见 [11.18](docs/RESUME_GENERATION_STANDARD.md)。
- **精简完成后的 A4 预览闭环**：确认 AI 精简后直接回到完整 A4 预览，待**更新后的真实文档**重新测量页高才显示完成栏；提供检查并导出高清 PDF、检查 ATS 文字 PDF、继续编辑和撤销。未达单页时可经确认再压缩全局留白，但不变更字号、事实或单模块间距。所有快捷导出仍调用原有独立预检与严格单页拦截。窄屏时顶部导航和操作区改为可横向滚动的独立行，A4 预览默认适配手机宽度，并保留手动缩放；不会缩小 PDF 正式导出尺寸。预览符合一页不等于正式 PDF 已验证。详见 [11.17](docs/RESUME_GENERATION_STANDARD.md)。
- **导出前质量检查**：两个 PDF 按钮均先打开独立审阅弹窗，依据当前导出画布提示预估页数、横向溢出、姓名/目标岗位/联系方式缺失、字体加载与跨页风险，并说明如何修正。画布未就绪或检测到明显横向溢出时不允许继续；普通多页情况仅提醒，不篡改内容。图片版无法复制文字，ATS 版的嵌入字体及文字层均须在实际 PDF 文件生成后再核查。图片版失败时**不会**偷偷改为 ATS 打印。**截图保真修复（2026-11-08）**：图片版已替换为支持现代 CSS 颜色的 `html2canvas-pro@2.6.3`，经典工程双栏的中文项目标题、日期和多行要点重叠已通过真实 Chrome PDF 修复验收，全部 12 款模板均已实测可导出。**内容安全分页（2026-11-08）**：图片 PDF 现在按真实文字行、模块标题与首条要点计算分页位置，逐页裁图；无法安全断页则取消导出，而不是静默切断文字。12 款匿名演示模板已通过真实 Chrome A4 双页核对。极端密集双栏与复杂自定义内容仍需人工检查；ATS 文字版的排版和可复制文字层独立于此。
- **ATS 分页与留白**：打印时只使用一次 12mm 物理页边距，不重复叠加视觉模板的内边距；项目链接使用单栏可用宽度。较短项目尽量完整留在一页，长项目允许在完整要点之间断页；标题与后续内容尽量保持衔接，保留原有全局/单模块间距，不自动删除文字或缩小投递字体。超长简历仍需检查打印预览。
- **GitHub 工程分析**：按需获取公开仓库的近期 Commit、部分目录、最多 4 份核心源码摘要；无需 AI 密钥即可点击「只读源码线索」查看 STM32、FreeRTOS、USART 等源码技术提示及原文件链接。需要 AI 写作时再明确授权发送公开摘要到所选模型，草稿通过事实守卫并由本人核对后才能导入；源码线索不等于个人贡献或测试证明。
- **岗位化证据建议与投递前审查（第四阶段）**：在「AI 岗位匹配」输入岗位 JD 后，本地规则优先推荐当前版本已存在且相关的项目、课程成绩、证书及奖项，带来源说明与「去编辑」，绝不自动补造技能或改动别的岗位版本。「开始投递检查」复用真实 ATS 浏览器排版预检，检查结构、事实账本异常、百分比成果、JD 关键词及页数，先展示最重要 5 项。未检查最终 PDF 本身前不会显示「投递就绪」或伪造招聘方 ATS 分数。详见 [岗位化资料与投递审查](docs/JOB_SUBMISSION_REVIEW.md)。
- **JD 匹配与润色**：使用顶部选择的已配置 AI 模型；建议不能视为实际工作经历或工程验证的证明。
- **AI 简历导入审阅**：文件/文本经 AI 解析后先显示待审草稿；本人逐项核对并确认才创建版本。覆盖时先提示字段差异；本地保存来源与核对状态。

- **母版资料（证据附件）**：顶部「母版资料」是所有岗位简历版本共用的证据候选库。上传 PDF / PNG / JPG / WebP 成绩单、奖状、证书或实习证明后自动使用当前兼容模型读取，无需额外授权勾选；上传前会说明本地/云端处理及数据风险。同一文件按 SHA-256 内容指纹去重，即使重命名，读取过就直接复用结果，不重复调用模型或占用文件名额。已读取的事实、原文摘录及冲突提示保存在当前浏览器 IndexedDB，但不会未经人工核对直接覆盖正式简历。原件与识别结果不随 JSON/PDF 备份，清除站点数据会丢失；未配置模型时可先保存待处理。详见 [母版证据资料](docs/EVIDENCE_ATTACHMENTS.md)。
- **Word / PDF 母版原稿与按需提取（P0-A）**：点击「母版资料」→「添加 Word / PDF」，原文件立即存入本机母版，**不自动提取、不修改或调用 AI**。需要编辑时点击「一键提取」，从可复制文字的 DOCX/PDF 生成可编辑副本，确认保存后 AI 只使用最新结构化内容，不再读取对应原件。图片式 PDF 暂无可靠内置 OCR，明确提示。详见 [母版内容库工作流](docs/MASTER_CONTENT_WORKFLOW.md)。
- **共享母版选材与可选 AI 整稿专业改写（P0-B）**：从已有内容库选择项目/经历、教育、技能与奖项，通过 JD 关联排序，先查看完整只读 A4；可直接新建岗位版本，也可**主动点击「用 AI 专业改写」**，将有限的安全描述字段交给已配置模型并在**两份完整 A4**中查看带原文依据的改写、逐项选用后新建独立版本。校验模型返回的数字、技术、职责与项目阶段风险，绝不自动上传原始 Word/PDF、修改学校姓名等事实字段。无模型仍可用本地流程。新增[可复现的四岗位质量评测](docs/ROLE_RESUME_QUALITY_EVALUATION.md)：当前未配置模型，已通过 23 个匿名离线规则样本，**真实 AI 模型专业质量仍未实测**。详见 [母版内容库与生成流程](docs/MASTER_CONTENT_WORKFLOW.md)。
- **母版自动分级检查**：附件识别后在本地自动整理清晰候选，无须逐字段点击确认；同一机构、同一字段跨不同内容文件一致时显示「多材料一致」。识别值与来源摘录不符、母版材料互相矛盾或与当前简历的对应字段有差异时才突出显示。正常事实默认折叠，可按需展开。此分级不是官方真实性认证，仍不自动覆盖正式投递简历。
- **母版轻量检索**：JD 诊断与 AI 单项润色按岗位检索最多 10 条教育/奖项/证书候选，及少量本人已确认收录的项目/工作经历摘要；不重复上传 PDF/图片、不引入向量数据库，也不把资料自动当作已认证事实。详见 [证据检索约束](docs/MASTER_EVIDENCE_RETRIEVAL.md) 与 [母版内容流程](docs/MASTER_CONTENT_WORKFLOW.md)。
- **母版候选采用与事实账本（第二阶段）**：仅在人工核对后将安全定位的证据候选应用到当前简历版本，写入 `factLedger`、记录来源、支持撤销，不自动认证学历/证书、不自动覆盖其他岗位。
- **结构化证书、奖项和课程成绩（第三阶段）**：同一份本地母版附件在各岗位版本间共享、按需读取；用户明确核对后可在**当前**岗位版本中创建新证书/奖项，或将某门课程成绩、加权均分分别采用到教育条目。证书与奖项仍复用现有版块，但有独立类型、颁发机构和日期；课程成绩按学校、课程名和分数结构化保存，与 GPA 分离，**不会未经选择自动挤进 A4 投递页**。已采用事实关联 `factLedger` 来源并支持撤销，其他岗位版本不会被暗中覆盖。详见 [结构化母版事实与多岗位复用](docs/STRUCTURED_MASTER_FACTS.md)。
- **全场景简历写作准则**：AI 简历制作、单项润色、JD 定制与篇幅精简现共用跨行业、跨资历的务实标准，适用于实习、校招、社招、资深岗位和转岗。真实已做的工作可积极突出职责、方法与交付价值；普通自述不强制逐句出具第三方证明，缺少数字也不强制编量化结果；仍防止虚构能力、任职、绩效数据或错误升级完成状态。保留「AI技能库」的创建、导入、编辑、选择与自动调用能力，但将此前的内置与自定义技能内容及选中状态一次性清空（首次在当前浏览器打开新版应用时执行，仅处理三个技能专用存储键）；此后新建的技能不再被清理。没有技能时直接按独立的统一写作准则润色，原始简历与岗位版本不受影响。详见 [RGS 第 1.1 节](docs/RESUME_GENERATION_STANDARD.md)。
默认简历是**演示数据**，不是真实求职者的经历，也不能直接用于投递。

## 画布交互

- **单击文字**：直接出现编辑框，单行按 Enter 保存，多行按 Ctrl+Enter 保存；Esc 取消，点击其他位置也会保存已修改的内容。
- **单击模块空白区域**：打开左侧对应编辑表单，适合添加条目、修改照片以及处理未在画布显示的字段。
- **拖动模块**：拖拽模块调整顺序，双栏版式也支持跨栏；单击编辑不会改变模块排列。
- **调节模块间距**：顶部「模板与版式」→「模块垂直间距」调节全局值（0–40px）；下方「单独调整模块间距」可让每个模块自定义上方留白、独立重置或全部恢复全局。所有 12 款模板及 ATS 打印版共享这一设置；旧简历没有新增字段时保留模板默认间距。模块的独立设置跟随模块 ID 与简历版本/JSON 备份保留；调整会影响打印页数。
- **模块内部精细排版**：同一「模板与版式」面板支持三项独立滑块：项目/实习条目间距（0–28px）、模块标题与正文间距（0–20px）、项目/实习要点间距（0–12px）；单项或一键恢复模板默认。旧简历不含新字段时自动使用原有模板内部间距；新设置保存在当前简历样式及 JSON 备份，应用于 12 款预览模板和独立 ATS 文字版。过大的间距可能增加 PDF 页数，导出前需检查。
- 简历数据由现有本地保存机制管理；建议在完成正式简历后另存 JSON 备份。

## 统一简历生成规范

项目所有简历解析、AI 润色、GitHub 工程提炼、岗位匹配及正式导出，均以 [简历生成统一规范 RGS v1.1](docs/RESUME_GENERATION_STANDARD.md) 为后续实施依据。规范包含事实与来源等级、质量门槛、默认交互、可检验的 20 个验收案例，以及现有代码待修正项。**该文档是研发标准，不代表全部规则已经自动执行。** 已实现 P0 事实校验与 AI 旧结果保护，并增量实现 P1 导入草稿审阅和本地来源快照；仍需完整事实审核与真实模型联调；PDF 实测范围见第 11.6 节。 已完成的五个开源项目只读源码审查与复用决策见 [2026-11-07 技术审查报告](docs/OPEN_SOURCE_RESUME_TECH_AUDIT_2026-11-07.md)；本轮未安装、未运行第三方代码。

## 本地运行

需要 Node.js 24 或兼容版本。仓库采用 Bun v2 锁文件，可使用兼容该格式的 Bun 安装依赖。

    bun install --frozen-lockfile
    Copy-Item .env.example .env
    npm run dev

打开 http://127.0.0.1:3000 。如果只使用手动简历编辑和 PDF，通常不需要设置 AI 密钥；AI 功能需要配置选定服务商的有效 API Key 或可用的本地 Ollama 模型，勿提交密钥到 Git。

    npm run lint
    npm run test
    npm run build

### 多模型 AI 选择

顶部「AI 模型」下拉框现在支持在 Gemini、OpenAI、DeepSeek、Claude、通义千问、豆包、Grok 和本地 Ollama 的已配置模型之间切换。所有请求仍受到 RGS v1.1 事实安全规则约束；密钥只存于本机服务端。模型是否实际可用取决于账号、密钥及运行环境，当前尚未完成真实云端调用验证。配置、文件能力、隐私风险详见 [多模型配置与安全说明](docs/MULTI_MODEL_SETUP.md)。

### PDF 导出说明

「一键高清 PDF」保留所选视觉模板，但文字不可选择，**不推荐用于 ATS 投递**。「ATS 文字 PDF」使用单栏黑白版、无照片、每页 12mm 边距；在 Chrome / Edge 打印窗口选择「另存为 PDF」，并检查打印预览。若预计超过一页，会提示选择继续多页或返回编辑，不会自动删掉内容。

**ATS 字体规范**：独立打印页固定中文优先微软雅黑（若缺失则回退到已安装的 PingFang SC / Noto Sans CJK SC）、英文 Arial，正文基准 10.5pt、姓名 22pt、求职岗位 13pt、模块标题 12.5pt；视觉展示版仍使用原模板设计语言。字体选择与最终 PDF 嵌入是两回事：Windows Chrome 实测 Arial、微软雅黑常规与粗体均被子集嵌入，其他系统必须使用其实际可用字体再回检。

**文件级 QA**：安装了可选 PyMuPDF 的 Windows Python 3.12 环境可执行 `py -3.12 tests/verify_ats_pdf.py --require-chinese --expect-font Arial --expect-font MicrosoftYaHei --require-embedded-fonts "<PDF完整路径>"`，检查真实 A4 输出、中文文字层、字体嵌入、空白页、乱码和越界。其他系统应修改预期字体名称。此检查不是招聘平台官方 ATS 验证；使用真实简历时请在本地执行，不要上传文件。

## 数据安全与使用边界

- 本地数据主要保存在浏览器 localStorage 中。浏览器清理数据、换设备或使用共享电脑可能导致丢失或泄漏；建议手动导出 JSON 备份。
- 开发服务默认仅监听 127.0.0.1。**不要在没有鉴权、限流及安全审查的前提下设置公网 HOST 或暴露 AI 接口**。
- GitHub 分析只读取**公开**仓库；源码、提交和 README 是不可信输入。它们不能证明简历持有人的实际贡献，也不能证明硬件已验证或性能已达标。
- 不应将真实简历、照片、证书、上传文件放进 src/data/ 示例数据或 public/ 静态资源目录。私有资料保存在被忽略的 _private/ 目录，且不应被部署。
- 即使后续将当前代码版本中敏感文件移除，**GitHub 旧提交历史仍可能保留这些文件**；历史清理与公开远端更新必须经过明确授权。
